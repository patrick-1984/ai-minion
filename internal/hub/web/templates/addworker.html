Linux or macOS

Run this in the terminal of the user whose sessions the Worker will serve. Choose what to share, then check the fingerprints in the startup summary. The Worker runs in the background and starts again at boot or login. Without a terminal the Worker shares all sessions; to keep them private, change --non-interactive-share all to none or later and choose in the Hub.

Linux system service (sudo)

Use sudo to install a system service on Linux with systemd. The sharing question lists the sessions of the user who ran sudo. Choose r there to run the Worker as root and serve root’s sessions instead. Without a terminal the Worker shares all sessions (the purpose of a Worker); change --non-interactive-share all to none or later to choose in the Hub instead.

{{template "fold" .Fold.System}}

Windows (PowerShell)

Run this in a normal PowerShell window. The Worker starts in the background and returns at each logon. Like the Linux and macOS commands, it carries the token, which stays in your PowerShell history.

{{template "fold" .Fold.Windows}}

Docker

Downloads bootstrap.sh, enrolls using a temporary container, and starts the enrolled Worker with Docker’s restart policy. The container hosts its own tmux sessions. Without a terminal the Worker shares all sessions (the purpose of a Worker); to keep them private, change --non-interactive-share all to none or later and choose in the Hub. The identity and settings stay in the data volume.
