# Usage verification

This pass exercised the Usage wave with isolated SQLite state, a temporary HTTPS Hub, and synthetic provider and credential data. It builds on the [implementation acceptance table](README.md) and [provider source verification](verification-sol.md).

| Check | Result | Regression evidence |
| --- | --- | --- |
| Weekly pace and quota coverage | At the midpoint, 15%, 50%, and 85% used produce Within pace, On pace, and Ahead of pace. Their linear projections are 30%, 100%, and 170%. Zero stays a measured value. A missing fraction or duration leaves pace unknown, and an expired limit is stale. The comparable weekly mean includes a current zero and a current 50% as 25%, excludes an older report of the same account, and keeps model scopes, currencies, and other durations separate. | [Page labels](../../internal/hub/web/usage_quota_boundary_test.go) · [Aggregate cohort](../../internal/ops/usage_quota_boundary_test.go) |
| Bucket joins and isolation | Two sessions linked to one subscription contribute one account to their session bucket. The same bucket can show an API credential in Accounts while excluding it from subscription capacity. A provider bucket filters linked sessions and history using the observed account. An old hourly snapshot keeps its attribution after the current session changes accounts. Bulk Worker moves and selected moves leave one membership per owner and kind. Unassigned sessions with unknown links stay unassigned. Narrowed Worker scope and another owner's bucket cannot admit extra rows. | [SQLite scope tests](../../internal/hub/store/usage_scope_boundary_test.go) · [HTTPS privacy and act-as tests](../../internal/hub/server/usage_http_verification_test.go) |
| Collector start, throttle and privacy | Real HTTPS Start returns collector state and refuses passive or incompatible providers. Repeating the same request preserves the live lease and a 49-minute Retry-After. Reassigning a former active Worker hides its identity and historical schedule, and the remaining collector resumes after the existing cooldown. An idle passive account keeps its source timestamp despite a fresh Worker session scan, and its old measured zero appears as stale in the aggregate. | [HTTPS collector tests](../../internal/hub/server/usage_collector_boundary_test.go) · [SQLite freshness test](../../internal/hub/store/usage_scope_boundary_test.go) |
| Credential identity and disclosure | The same ten-character prefix gives separate identities for different underlying keys and endpoints. Neither a short key found in a synthetic endpoint authority nor the raw authority, private path, or fingerprint seed reaches the projection. An endpoint with query parameters or a fragment is refused. The existing store regression checks serialized and SQLite data for complete key material. | [Worker credential tests](../../internal/worker/agent/usage_credential_boundary_test.go) · [SQLite persistence tests](../../internal/hub/store/usage_test.go) |
| Portable API | Each of the six Usage POST paths resolves its request, success, and error components. Actual Go DTO JSON validates with explicit nullable fields and observed zeros. Worker inventory documentation omits internal account-poll and event-cursor request fields. The checked-in OpenAPI file matches the generator byte for byte. | [Schema test](../../scripts/usageschema/schema_verification_test.go) · [OpenAPI](openapi.json) |

The bucket projection, HTTP Start and credential tests also ran with an overlay of the prior `626acfe` implementations. The overlay reproduced empty cross-type bucket results, missing mutation response state, acceptance of an incompatible provider, an invalidated duplicate-start lease, an early retry after the lost completion, and a short key in the public label. Three subsequent race-enabled runs passed the focused suites across `internal/ops`, `internal/hub/store`, `internal/hub/web`, `internal/hub/server`, `internal/worker/agent`, and `scripts/usageschema`.

A warm Linux amd64 benchmark processed 100 SQLite transactions of 50 synthetic sessions at five-second logical ticks, averaging about 2.75 ms per batch on an AMD Ryzen AI Max+ 395. This measures local unchanged-counter ingestion without network latency.
