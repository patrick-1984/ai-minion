# Native usage source verification

Checked on 2026-11-21 against primary provider documentation and upstream source. Commands and fields apply to the cited interface version. Verify support on the installed binary or collector before enabling a source.

| Source | Canonical mapping | Collection boundary |
| --- | --- | --- |
| Gemini CLI headless JSON and stream-json | For a run the owner already invokes, read the final result's per-model counters. Carry forward the native session ID from the stream initialization event, or supply the run identity explicitly. Map `prompt`, `candidates`, `cached`, and `thoughts` to input, output, cache read, and reasoning independently where present. | Headless mode runs inference. It is a passive result source for existing runs. Process only the final stats and allowlisted identity fields locally. Message text, tool inputs, tool output, and error bodies stay at the source. [Gemini CLI headless mode](https://geminicli.com/docs/cli/headless/) |
| Gemini CLI OpenTelemetry | `gemini_cli.token.usage` has native input, output, thought, cache, and tool categories with model attribution. A producer using cumulative export replaces counters at the same series identity. A delta exporter increments them once per observation. | Use an explicit local producer that exports allowed metrics. Avoid default prompt logging and full event payloads. The public telemetry documentation describes token metrics, without an account quota export contract. [Gemini CLI telemetry](https://github.com/google-gemini/gemini-cli/blob/main/docs/cli/telemetry.md) |
| Gemini CLI Google sign-in and Code Assist quota | The native configuration reads model buckets containing `modelId`, `remainingFraction`, and `resetTime`. Translate a valid fraction to percent used, preserve its model pool and unit, and retain the upstream reset. Leave duration and pace unknown when the payload omits duration. | Google distinguishes personal/organization sign-in, Gemini API key, and Vertex AI. Gemini API/Vertex usage must stay in accounts with their actual auth type. The public command documentation still mentions quota in `/stats model`. Maintainers distinguish session statistics from daily account limits on `/model` and the quota footer. Exact status display depends on the installed build. The Code Assist implementation is useful for mapping; an independent public API contract for Google sign-in quota polling was not found. Use a local native producer or an explicitly designated idle collector, with unavailable status otherwise. | DeepSeek Chat Completions and FIM | Use the response ID to deduplicate a completed request. Translate `prompt_tokens`, `completion_tokens`, `prompt_cache_hit_tokens`, and optional `completion_tokens_details.reasoning_tokens`. Prompt tokens already include hits. Accumulate request totals once within a session. | Read usage from a response to an existing request, including the terminal usage chunk when streamed. Keep missing counts and charges unknown. Public model prices alone are insufficient to mark a charge as reported. [Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/) · [FIM](https://api-docs.deepseek.com/api/create-completion/) · [Pricing](https://api-docs.deepseek.com/quick_start/pricing/) |

Query the balance only from an explicitly configured local credential source if requested. | OpenCode local statistics and native events | On versions that support it, `opencode stats --json` reports historical aggregate usage. For attribution to a stable session, use the local API or native `session.usage.updated` event. In the Console inference payload, input excludes cache reads/writes and output includes reasoning. Distinguish declared price estimates from charges using the native estimated flag. | Read from a user-configured existing local server or producer. Its event stream can contain model text and tool content. Project usage events in place. Project or workspace aggregates cannot be copied onto every session. [CLI commands](https://opencode.ai/docs/cli/commands/) · [Local API](https://opencode.ai/docs/api) · [Inference API](https://opencode.ai/docs/console/api/inference/) |
| OpenCode Go subscription | The local API documents experimental `GET /api/experimental/usage/limits`. It returns the current location's signed-in workspace allowance, or null. Go meters expose rolling, weekly, and monthly utilization, `limited`, and Unix millisecond `resetsAt`. Console budget dollars and reset times are distinct. | Version-gate this route on a designated local server; respond to unsupported, unauthenticated, and unavailable states. Identity must come from the selected workspace/profile. Do not start a listener on a public address or inspect browser sessions. [OpenCode API](https://opencode.ai/docs/api#usage) · [Console Activity](https://opencode.ai/console/changelog/activity) · [Console Budgets](https://opencode.ai/docs/console/budgets/) |
| Cline | Task management reports duration, token counts, and cost. Its UI cost tracks model pricing as an estimate. Attribute a task to the configured provider only when the local source supplies evidence. | The published task guide establishes owner-visible metrics. No stable read-only subscription collector was identified there. Keep separate from provider account telemetry. [Cline task management](https://docs.cline.bot/core-workflows/task-management) |

Claude Code's status line describes recent context and session totals in the same object. Context/input from the most recent response belongs to a context gauge. Do not sum that gauge as cumulative session tokens. A rate-limit window requires its own observation timestamp and becomes stale on expiry. Claude Gateway spend limits are monetary. [Claude Code status line](https://code.claude.com/docs/en/statusline)

## Verification

- The Hub synthetic views exercise all seven routes with signed-in admin and user roles. Form tests assert selected rows, full Worker and domain-wide moves each pass only their own selection scope. The act-as fixture checks the page skips private operations and strips bucket filters. The real Hub HTTP tests exercise the same API dispatcher over TLS with a temporary SQLite store.
- The Worker fixture confirms an approved Usage report includes the unshared session while ordinary list, snapshot, capture, and send remain restricted. The Usage response omits the synthetic console and task text.
- The generic CLI inventory and subscription overview entry points reuse Hub operation registration. Their fixtures connect only to local HTTPS with a fake credential and verify the local Worker backend is never called.
- The Linux amd64 SQLite benchmark measured 1.187 ms per transaction over 100 batches of 50 synthetic sessions at five-second logical intervals on an AMD Ryzen AI Max+ 395. This warm local run measures ingestion without network latency. The tested model retains bounded hourly snapshots and trims closed session records and old snapshots according to their separate retention periods.
- The usage preview was served from a synthetic loopback Hub. Shared Chrome's Playwright MCP timed out during CDP initialization, before it created a reported preview tab. Browser screenshots and the responsive light/dark visual check remain pending. No production credentials or real provider accounts were used.
