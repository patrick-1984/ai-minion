# Native usage sources and registration

## Operating the feature

1. Open **Usage → Workers** in the Hub. A Worker can be offline, unavailable, unsupported, waiting for local registration, or reporting. **Scan installed harnesses** checks recognized executables in the Worker's own execution environment. The UI never asks for a provider password or API key.
2. On a newly enrolled Worker, run `minion worker config usage` to review the fingerprint, owner and metadata disclosure. Run `minion worker config usage --accept` to authorize that enrollment. A new metadata-capable enrollment first receives its signed welcome so its local operator can verify the identity. Its connection closes before starting control, event or pipe handlers until accepted. The next reconnect activates it. Replacing the Hub key or changing the owner requires a new acceptance. A previously existing, fully identified enrollment keeps its prior console agreement. It reports no new telemetry until the operator accepts. Old clients and pending registrations represent gaps in coverage.
3. The Worker owner and administrators see metadata from all sessions after acceptance. The Worker uses terminal-host metadata to identify current sessions, including unshared ones. The tmux projection requests the working directory, native session identity and active executable. It does not request a pane capture, task description, arguments or process environment. Local session-sharing permissions still control console operations.
4. In **Accounts**, inspect the source, observation time, windows and collector. One authorized Worker probes a given native subscription at a time across the domain. An observed session can also be selected as a passive source. That selection routes quota observations from a configured exporter. It does not type a command into a console or manufacture a report when a harness lacks a machine-readable source. A private display name and order apply only to the signed-in person's view.
5. Use **Token buckets** to organize sessions or provider identities. Assignment does not affect collection. A domain administrator sees domain telemetry and their own buckets. An impersonated view cannot save or browse another person's bucket definitions.

## Local native exporters

The Worker can accept a native event or status object on standard input. Configure this at the source producing the observation. The exporter reads at most 256 KiB, decodes allowlisted fields and persists only those fields. The Worker publishes them on its registered connection. Existing status-line programs may continue receiving their original input. Minion does not rewrite harness settings.

| Native input | Local command |
|---|---|
| Claude Code status-line JSON | `minion worker config usage record claude-statusline --session build --provider Anthropic --account ACCOUNT_FINGERPRINT` |
| Claude Code lifecycle hook JSON | `minion worker config usage record claude-hook --session build` |
| A Codex thread token notification | `minion worker config usage record codex-token-usage --session build --provider OpenAI --account ACCOUNT_FINGERPRINT` |
| Gemini's final JSON with per-model stats | `minion worker config usage record gemini-result --session build --native-session RUN_ID --provider Google` |
| Gemini's native subscription quota object | `minion worker config usage record gemini-quota --session quota-collector --native-session COLLECTOR_ID --provider Google --subscription-profile work` |
| A DeepSeek response from an OpenCode adapter | `minion worker config usage record deepseek-response --session build --native-session RUN_ID --harness opencode --provider DeepSeek --endpoint https://api.deepseek.com` |

Use the complete opaque account ID from the Hub's usage_list response for an already-discovered subscription. An explicit subscription-profile label allows an operator to bind a provider without a native stable account ID. The choice is local to its configured producer. Reuse the same label only for the same provider subscription across Workers of this Hub. Where the terminal launches the exporter inside its tmux pane, the session name can also be resolved from that pane. An optional stable event ID makes retries of notifications without their own IDs idempotent.

## Credential identity and disclosure

Normal subscription inventory uses native status and never needs a fingerprint-secret file or a provider key file. The Worker hashes the provider's native stable account identity locally. When a provider only exposes a login email, the deterministic identifier is a pseudonym, and a guessed address can be tested against it. Use explicit profile binding for ambiguous workspace identities. The display masks the native login's local part, shows its domain and adds a short digest suffix to distinguish workspaces. A private alias can identify a work or family subscription in your own view. Account mode can be known even when no credential identity is safely available.

API identities combine provider, canonical endpoint and credential. URLs containing credentials, queries or fragments are refused. Only the fingerprint and a display hint leave the Worker. Known issued, sufficiently long key formats can use the registered Hub's public identity as a domain-specific salt. A public salt separates domains and does not protect guessable credentials from a dictionary attack. The one-click path uses a fixed vendor environment key only if native auth status identifies that exact credential source and its endpoint. It does not inspect other processes, execute credential helpers or read credential databases. A custom provider, uncertain origin, or short key may still yield an API mode while exact identity remains unavailable.

For a native exporter explicitly given an endpoint, the fixed vendor key in that producer's own environment can supply attribution. Advanced integrations may instead explicitly name a private credential file and a private, randomly generated fingerprint seed of at least 32 bytes. Give matching trusted Workers the same private seed if they must deduplicate those custom credentials. The secret and full credential remain in the local process. A short key gets no prefix. A long printable key may show the first ten characters, an ellipsis and a digest suffix; the identity is the full digest. A prefix collision cannot join distinct accounts.

## Storage, pacing and access

The authenticated Worker identity and current owner determine which database rows a report may update. A reassignment removes old telemetry and invalidates stale authorization. The Hub stores one current sample per session, cumulative snapshots per UTC hour for 30 days, bounded diagnostics/events for seven days, and closed session details for 90 days. A complete successful poll is required to conclude a session is no longer observed. A failed enumeration is not a stop. Repeated cumulative samples and request IDs do not create another billable increment.

Subscription comparisons use distinct account identities and each provider's scope, unit, and observed window length. Known percentages are an unweighted mean of comparable observations. The display includes known, stale and unknown coverage. If the denominator or applicable window is absent, the percentage is unknown. A missing reset or duration prevents pace classification. Five percentage points on either side of the elapsed share of a valid window is on pace. The default source becomes stale after 15 minutes. A recorded reset that has already passed makes an old value stale.

Each account has at most one in-flight lease. A crashed poll still consumes its minimum five-minute interval. Important task/subagent completion events coalesce under that floor and do not shorten a provider cooldown. A native rate-limit indication with a retry delay sets a lower bound, transient failures exponentially back off, and positive jitter prevents synchronized retries. Passive observations already produced by a harness consume no additional provider requests.

The versioned HTTP schema is in [openapi.json](openapi.json). Use the same read-only usage_list and usage_bucket_list operations from Hub-connected MCP clients. The account's effective permissions and resource scope apply at HTTP, CLI, MCP and Hub UI entry points. Bounded, keyset-paged events and history sections expose fixed event types and cumulative sample values. They carry no free-form task, log, command or console payload.

The explicitly disclosed `minion worker up --accept-usage` option authorizes one enrollment. It works with foreground, service and configure-only handoff. A 30-minute, local one-shot binds to the selected server URL, any known public Hub pin, and any existing Worker and owner. The Worker consumes it after verifying and saving the welcome. A legacy Hub consumes the one-shot without enabling monitoring. It is never a standing flag on the supervisor's `worker run`. The local review supports `minion worker config usage --json` and optional expected Worker ID, owner and Hub fingerprint guards when accepting a previously displayed registration.

Claude users can explicitly install the local integration, including composition with a pre-existing status line. See [Claude exporter setup](claude-integration.md). Codex and Gemini producers can supply `--observed-at` with the original RFC3339 timestamp when forwarding delayed metrics. Without a native timestamp the measurement records Worker receipt time and marks the clock source accordingly. The current-profile native Codex and Claude account reads include plan type when the provider reports it. A native producer that omits a folder does not erase the folder observed by the terminal host.

**Start native collector** requests a dedicated status-only reader for a supported, native-attested Codex account. Choose an eligible Worker or automatic selection. Repeated clicks coalesce and preserve the existing cooldown. Choosing a passive session selects its published source. Claude and Gemini currently have no implemented prompt-free background query for personal subscription windows. An idle Claude or Gemini producer can therefore show stale or unknown data until the harness publishes again. A source selection cannot turn an idle passive observation into a current measurement.

An **All subscriptions** mean appears only for broad Anthropic and Codex coding allowances with the same reported duration and period. It averages the percentage of each distinct account's own allowance, and separately counts unknown and stale accounts. Model-specific limits and unlike units remain in separate groups.

A session bucket filters subscription views through the distinct account identities its visible sessions reported. A provider bucket filters sessions and history through their linked provider identities. An hourly observation keeps the account attributed at capture even if the session later switches to a different account. Unassigned has its ordinary meaning for the kind being viewed. Filtering cannot reveal membership in another user's buckets or telemetry on an inaccessible Worker.

## Changing-session storage test

On Linux amd64 with two Go scheduler threads, 360 logical five-second ticks covered 30 minutes. One third of the sessions changed cumulative counters at each tick and an authenticated-scope account read ran every fourth tick. With 20 sessions the average batch including those reads took 1.40 ms and the slowest measured write was 7.01 ms. With 50 sessions the average was 3.21 ms and the slowest write was 8.15 ms. Each case retained one hourly sample and one initial lifecycle event per session over this single observed hour, including after 18,000 candidate session updates in the 50-session case. These measurements are local warm SQLite timings, not network or provider latency. Reproduce with `GOMAXPROCS=2 go test ./internal/hub/store -run '^$' -bench '^BenchmarkUsageMixedSessions$' -benchtime=360x -count=1`.
