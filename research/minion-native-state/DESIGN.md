# Native session state for Minion (A93)

On baseline `f7170899`, both captured Claude Code 2.1.33x panes returned `stable` from `sessions_list`. One had a running shell and three background tasks. The other was waiting for a background agent and a workflow. The input editor was ready in both.

## Binding and projection

The exporter asks the authenticated local Worker for its effective tmux socket and matches the socket, server PID, pane ID and session creation time. It verifies that the running harness is an ancestor of the hook and owns the pane's foreground process group. The reader rechecks process lifetime and current harness PID. Session renames require fresh evidence under the new name. Platforms without verifiable process identity use the screen fallback.

Worker migration 0013 creates a local SQLite event journal. Each entry carries the pane binding, harness, process birth identity, grant-scoped hashes of native session and entity IDs, a fixed event kind, optional sanitized registry and local receipt time. Grant verification and insertion share one transaction. Reassignment or revocation clears the journal. The exporter discards prompt text, transcript paths, commands, descriptions and cron payloads; the only transcript content it decodes is the `/rename` command record (see Session name). The Hub receives only display state, source, a bounded reason, and last lifecycle event time.

* A parent stop ends its turn. A fresh registry replaces runtime facts. An explicit empty array clears them. An absent registry leaves prior facts intact. Planner items have a separate `open task` label. With a known empty registry they can coexist with idle. Without registry coverage they conservatively keep the display busy until completion or expiry.
* Pending permission or input takes precedence. A tool batch clears its own agent's wait. Otherwise any live foreground turn, shell, subagent or workflow keeps the session busy. Input guards continue to use the immediate pane classification and reviewed dialog.
* Replay uses receipt order with the database sequence breaking ties. The current SessionStart fences previous harness sessions. Child lifetimes are keyed by ID. Liveness expires after 15 minutes of silence. A heartbeat cannot extend a semantic fact beyond 30 minutes. The reader caps replay at 1,024 events and falls back on overflow. Writes prune old entries after 24 hours.
* Missing, stale, incomplete or untrusted evidence selects labeled screen fallback. A visible permission dialog retains its reviewed binding, and a positive background footer can cover an omitted native registry. Hitting a payload limit, a missed async hook, or ending a turn through another hook can temporarily leave state incomplete. A subsequent native transition or registry snapshot reconciles it.

## Session name (A96)

The Sessions table shows the name the user gave the conversation inside the harness. Claude Code 2.1.33x has no hook field for it. The status line's `session_name` carries the `/rename` or `--name` name, but it falls back to the AI-generated title, and the `custom-title` transcript entry it mirrors is also written by an unnamed `/branch` (a title derived from the first prompt) and by prompt hooks, with no field that tells them apart. So the exporter keeps `session_name` only on positive evidence that the user typed it: the claude process (pid and birth verified) was started with `--name <name>` / `-n <name>` (read from `/proc/<pid>/cmdline`, Linux), or the transcript holds the `system`/`local_command` record Claude Code writes for the user's own `/rename <name>`, whose `<command-args>` equal the name. A prompt that quotes the command is a `user` entry and does not count; `/rename` without an argument (a generated name) has no argument and does not count. Otherwise the session shows no name (a name known before is cleared). The transcript is opened only as `<profile>/projects/<project>/<session id>.jsonl` beneath the verified profile directory (the directory of the exporter's manifest), walking down with `openat` and `O_NOFOLLOW`, non-blocking, and only when `fstat` says it is a regular file. Only lines up to 64 KiB that contain `"local_command"` and `/rename` are decoded. The search is incremental: a keyed digest of the name and the file identity plus the offset searched so far are stored, each callback searches at most 32 MiB of what the transcript gained since (within the callback's 900 ms budget), and a transcript that cannot be opened records nothing, so the next redraw retries. Writes are ordered by observation time (an older callback finishing last never overwrites a newer write, clears included). The name is sanitized (no control or format characters, white space folded, at most 80 runes), stored in Worker table `harness_titles` (migration 0014) per pane generation and grant-scoped native session hash, and cleared with the journal on reassignment or revocation. The transcript path itself is discarded. The reader reports the name of the native session the pane's harness process runs now, fenced by its latest session start like the native state (a delayed hook of the conversation before `/clear` cannot bring back its name), while its process lives and is the pane's harness, also when the state falls back to the screen. It travels as the optional `harness_name` of the pane state detail; the Hub sanitizes it again and binds it to the owner the reporting connection was admitted under: the session list, the event-stream snapshot and queued events show it only while the Worker still has that owner, and a reconnect under another owner drops the cached names. The CLI sanitizes it again at display. Older Hubs ignore it and older Workers omit it.

Codex 0.171 keeps thread names in `~/.codex/session_index.jsonl` (`id`, `thread_name`, `updated_at`), but it also saves automatic titles there ("An automatic title is still being saved" in `/rename`), with no field that tells them apart, and its hooks carry no name. Codex names are therefore not shown.

## Installation and checks

Installation follows the existing usage-consent loop. The Claude exporter preserves the previous status line. Codex hooks are installed for supported existing profiles, with native review through `/hooks`. The Worker honors `usage_claude_exporter=off` and `usage_codex_exporter=off`. Running sessions need to load the new hooks.

Regression checks cover both owner screens, empty and absent registries, overlapping work and permission waits, expiry, consent changes and process replacement. A private tmux test feeds a Claude Stop payload with a live shell through the exporter and the real Worker, reads snapshot and list, then respawns the pane to verify the old native state disappears.
