# Native harness attachment and revocation

Public docs and source inspected on 2026-11-21. The workspace has Claude Code 2.1.330, Codex 0.171.0 and OpenCode 2.0.29. The following are source findings. Native two-session fixture runs are required before advertising a supported version and mode.

| Harness | Strongest candidate for a live session | Session-scoped setup and removal | Unprepared running terminal |
| --- | --- | --- | --- |
| Claude Code CLI | A stdio server registered for one launch can add and remove tools using MCP `notifications/tools/list_changed`. Optional launch-scoped hooks can supply guidance on an eligible user turn and report native session changes. | Pass `--mcp-config` and, if needed, `--settings` with configuration owned by this launch. A dormant connection serves an empty catalog and no master instructions. Check that the client stays connected on an empty catalog and drops stale tools after a successful refresh. Prefer dynamic tool descriptions over a static plugin loaded for the process lifetime. | Detection supplies the harness kind. Current docs establish no supported external registration method that targets an arbitrary existing terminal conversation. Offer a deliberate session-local launch or a supported host connection when already configured. |
| Claude Agent SDK | A caller that owns the session's `Query` can add and remove an MCP server with `setMcpServers`. Interactive registration belongs to that SDK host. | Keep the full set of other SDK-managed servers when making replacements. Require a supported version for tool withdrawal, including v2.1.285 for dynamically added stdio/HTTP/SSE removal and v2.1.286 for in-process tool withdrawal. Validate the SDK response and next-turn catalog. | The SDK method needs the live owned `Query`. A plain discovered TUI offers no such handle. |
| Codex CLI and app-server | Isolated CLI process/config or a host-owned thread with a thread-start MCP configuration and a unique connection. Tag `rust-v0.171.0` has ordinary `list_changed` support behind `mcp_tool_list_changed`, under development and disabled by default. `mcp_connection_sharing` is also experimental and off by default. | Use per-invocation `-c` or host-owned thread configuration. Where supported, CLI `--no-daemon` avoids a shared daemon. Hooks can add context at `SessionStart` and `UserPromptSubmit` from a trusted lifecycle event. Prove the actual app-server keeps MCP connections and cached catalogs distinct and honors removal and resume. | `config/mcpServer/reload` queues refresh from disk across loaded threads. `skills/extraRoots/set` is process-wide. The pinned `thread/settings/update.disabledPluginIds` saves the selection without filtering capabilities. There is no proven safe arbitrary live attachment in this release. |
| Gemini CLI | A registered server's tool-list change triggers rediscovery in current source. `BeforeAgent` can supply context for the current turn and `SessionStart` receives lifecycle identity. ACP supplies servers in a client-owned session. | An explicitly isolated `GEMINI_CLI_HOME` or owned ACP session avoids project/user config edits. Use stdio under a trusted launch and keep harness approval behavior. Prove that an initially empty catalog connects and stays available, and that clearing or resuming a chat cannot reuse a lease. | `/mcp reload` restarts the local client manager. In-session enable/disable manages already configured servers. Neither supplies an external API for targeting an unprepared TUI. |
| OpenCode v2 | A deliberately installed server plugin can filter `event.tools` and add temporary `event.system` content from `ctx.session.hook("context", ...)` for the native session ID. Authenticated OpenCode MCP calls include native `ai.opencode/sessionID` correlation metadata. | Per-request projection is the strongest shared-server candidate. Prove masking for ordinary, auxiliary and tool-search requests, plus rejection of direct calls and absent or wrong session metadata. An already-owned single-session server can trial runtime MCP add/remove. Stop projecting on revoke and disconnect a dedicated registration where appropriate. | Runtime MCP add/remove/connect/disconnect and the plugin MCP reload act on a location. Two sessions in the same location can share that registry. Treat shared-location registration alone as unsuitable. |
| OpenCode v1, Qwen Code, Aider | OpenCode v1 differs from v2 and needs its own fixture. Qwen Code documents user/project MCP configuration and recommends restarting an existing process after adding a server. Aider supports read-only launch files and an interactive `/read-only` command. | Qwen needs a verified isolated configuration or host-owned adapter. Aider can read a private guide at a deliberate invocation and report no live integration. The guide must contain no credential. Aider's direct shell commands still need the verified Minion CLI backend to use master authority. | No live support claim for these modes. Detection can show how to open a supported attachment. |

## Evidence and constraints by harness

### Claude Code

- The CLI explicitly describes `--plugin-dir` as session-only and `--mcp-config` as a launch option. CLI `--strict-mcp-config` can discard unrelated MCP servers, so it is unsuitable for the normal additive launch path. Local-scope `claude mcp add` writes user configuration keyed by project and can affect sessions in the same working directory. `/reload-plugins` refreshes plugin state for the current TUI after ordinary installation and does not give the Worker an attachment endpoint. [CLI reference](https://code.claude.com/docs/en/cli-reference), [MCP scopes and live updates](https://code.claude.com/docs/en/mcp#dynamic-tool-updates), [plugin reload](https://code.claude.com/docs/en/discover-plugins).
- The interactive client refreshes tools, prompts, and resources after the corresponding notification. Print mode and Agent SDK refresh tools. A failed refresh can keep prior schemas, so enforcement must happen in the backend. `SessionStart` supports `reloadSkills` for known skill roots, and `UserPromptSubmit` can add context on a later turn. Use lifecycle identity from trusted events and fixture-test `/clear`, interactive resume and agent children. [Hook events](https://code.claude.com/docs/en/hooks), [Agent SDK controls](https://code.claude.com/docs/en/agent-sdk/typescript).
- Claude Remote Control exposes user interaction through Claude's app or website and must be enabled for the session. Its documented purpose does not include installing a session-only MCP server into the existing terminal conversation. An unprepared terminal has no observed supported session-only bootstrap path. [Claude CLI Remote Control flags](https://code.claude.com/docs/en/cli-reference).

### Codex

- The recommended test uses a unique stdio server registered for one CLI invocation or a thread that Minion's trusted client owns. `thread/start` and `thread/resume` accept config and developer instructions. `dynamicTools` and `selectedCapabilityRoots` are experimental creation-time fields. Dynamic tool declarations can persist on resume and do not provide a live removal contract. Even a usable isolated selected root requires tested reload, inheritance and cleanup. [App Server docs](https://learn.chatgpt.com/docs/app-server), [thread schema source](https://github.com/openai/codex/blob/rust-v0.171.0/codex-rs/app-server-protocol/src/protocol/v2/thread.rs), [versioned plugin settings semantics](https://github.com/openai/codex/blob/rust-v0.171.0/codex-rs/app-server/README.md#thread-plugin-settings).
- `mcpServerStatus/list` can inspect a specific thread's MCP connection. It does not configure that connection. Reload has no thread ID in the pinned request schema. An installed marketplace plugin generally loads in new sessions from shared state. Process-wide skill roots and plugin installation cannot enforce thread-only exposure in a shared daemon. [Pinned request schema](https://github.com/openai/codex/blob/rust-v0.171.0/codex-rs/app-server-protocol/schema/json/ClientRequest.json), [pinned feature defaults](https://github.com/openai/codex/blob/rust-v0.171.0/codex-rs/features/src/lib.rs), [CLI flags](https://learn.chatgpt.com/docs/developer-commands?surface=cli), [Plugins](https://learn.chatgpt.com/docs/plugins), [Hooks](https://learn.chatgpt.com/docs/hooks).
- `codex queue` queues a user message for an existing thread. It does not attach tools or provide reversible capability configuration. [Codex CLI](https://learn.chatgpt.com/docs/cli/reference).

### Gemini CLI

- Source registers a tool-list change handler and replaces that server's tool entries in the registries. Initial discovery via `discoverInto` reports an error for a server with no tools, prompts or resources. Its current manager handles that error without disconnecting in that branch, while the older `connectAndDiscover` path describes cleanup on empty discovery. `/mcp reload` restarts servers from the current manager's `allServerConfigs` and refreshes tools. Verify the real version and transport before committing to a dormant catalog. [MCP guide](https://geminicli.com/docs/tools/mcp-server/), [client source](https://github.com/google-gemini/gemini-cli/blob/main/packages/core/src/tools/mcp-client.ts), [manager source](https://github.com/google-gemini/gemini-cli/blob/main/packages/core/src/tools/mcp-client-manager.ts), [reload command source](https://github.com/google-gemini/gemini-cli/blob/main/packages/cli/src/ui/commands/mcpCommand.ts), [configuration](https://geminicli.com/docs/reference/configuration/).
- ACP supports session-level `mcpServers` at session setup, with lifecycle and transport details negotiated by the actual implementation. It does not imply changing server registration by connecting an unrelated client to an existing CLI conversation. [ACP session setup](https://agentclientprotocol.com/protocol/v1/session-setup), [Gemini ACP](https://geminicli.com/docs/cli/acp-mode/), [Gemini hooks](https://geminicli.com/docs/hooks/reference/).

### OpenCode

- OpenCode v2's documented runtime MCP routes take a location, and client-hosted experimental MCP connections expose tools while their socket is open. Plugin `ctx.mcp.transform` and `reload` reconcile at that runtime scope. A unique session identity is available at the request layer. Treat it as correlation supplied by the trusted OpenCode host, and require a verified lease and transport on every Minion call. The experimental per-session skill activation endpoint appends a skill message and resumes execution, so it does not satisfy passive activation at an existing user boundary or remove copied text. [OpenCode API](https://opencode.ai/docs/api), [MCP behavior and metadata](https://opencode.ai/docs/mcp-servers), [v2 plugin hooks](https://opencode.ai/docs/build/plugins/server/).
- OpenCode documents the different v1/v2 hook contracts. Per-request deletion and tool execution metadata are useful candidates only after version-specific tests include shared server/location, direct entry points and child sessions. [Plugin migration](https://opencode.ai/docs/build/plugins/migrate-v1/).

### Other detected harnesses

- Keep detection distinct from attachment support. Qwen Code's documented configuration writes shared user or project settings. Aider's read-only file option adds content to chat context. [Qwen Code MCP](https://qwenlm.github.io/qwen-code-docs/en/users/features/mcp/), [Aider options](https://aider.chat/docs/config/options.html), [Aider in-chat commands](https://aider.chat/docs/usage/commands.html).

MCP defines list-change notifications as invalidations. A verified client must refetch the catalog. Access revocation is still checked by Minion for all calls, including those using stale discovery, regardless of transport or protocol version. [MCP tools specification](https://modelcontextprotocol.io/specification/2025-11-25/server/tools).
