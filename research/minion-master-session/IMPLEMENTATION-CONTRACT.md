## Link protocol v1

Use a single `ev` control stream per participating Worker link and the existing one-request `ca` stream for each tool call. Add `master.session.v1` to the signed Worker hello only when the local adapter is available. A participating Hub echoes `master_session_v1: true` in the authenticated welcome only when it can serve the feature for that approved Worker. Omission on either side keeps the adapter inactive. Each side owns its local welcome struct. Never infer support from a binary version. [Worker features](../../internal/proto/features.go) · [Event substreams](../../internal/hub/workers/events.go) · [Worker call frames](../../internal/hub/workers/calls.go)

| Message | Fields and semantics |
| --- | --- |
| `master.open` and `master.report` (Worker → Hub, `ev`) | Both carry `seq` and `candidates[]` as a complete, bounded snapshot of prepared, locally verified, shared candidates. Each item contains `session_name`, opaque `incarnation_id`, `adapter` and optional last catalog result. The first snapshot opens an existing `Ingest.OnStream` lane. Report promptly on local changes and every 10 s while candidates are present. An empty snapshot withdraws them. Reject invalid, oversized or incomplete snapshots as a whole and invalidate stale leases. Never truncate into a valid snapshot. |
| `master.state` (Hub → Worker, same `ev`) | A complete replacement containing `serial`, `report_seq`, `ttl_ms` and `active[]`. Each active item carries `incarnation_id`, `generation`, `lease_id`. Empty removes every active binding. Push on nomination or revoke, as well as on reports. Use one ordered writer per link. Ignore late serials, retired incarnations or unknown report sequences. A local deadline is at most 30 s from the monotonic **send time** of the acknowledged report. An unsolicited push cannot extend the deadline beyond that. On stream loss both sides immediately invalidate its state. Reopening the control stream requires a fresh lease. Never log lease handles. |
| `master_call_v1` (Worker → Hub, `ca`) | `op.request` has the existing `request_id` and typed arguments `{incarnation_id, generation, lease_id, operation, arguments}`. Return normal `op.result` or `error`. Reject outer `api_key` and `source_session` and unknown or forbidden inner operations/arguments. The Worker sends through the captured authenticated link, without a retry on a new link. The Hub obtains Worker, owner and connection identity from admission. Use the handshake transcript identity already present in `Online.TranscriptHash` and carry it from the authenticated connection into both handlers. A new link for the same Worker cannot validate an old handle. |

The Hub owns lease creation and expiry. Use existing opaque-ID generation and in-memory link state. Schema migration stores only durable nomination state. The MCP client never receives lease material. The broker pins the helper to the proven terminal. Bind each published tool to the generation of its catalog, for example with a generation suffix on its MCP name. The local backend needs catalog state and `Call(ctx, catalogGeneration, operation, arguments, requestID)` over this verified peer. Compare the supplied catalog generation to the current binding. A stale native invocation after revoke and re-nomination must fail before the broker selects a current lease. The generation is public correlation data. Expose this backend through a dedicated session-only launch and master MCP mode. General REST, the shared local executor and call keys cannot substitute on failure. `/clear` may continue on the same terminal and peer. A new helper after death or an ambiguous, moved, renamed or replaced terminal retires that binding. Drop credentials, withdraw tools and reconcile only the artifacts owned by that launch.

## Admin mutation, storage and dispatch

Use `control_set_bound_master` behind the existing **Access > Minion control** page with the current admin permission and owner check. Its request contains `worker_id`, `session_name`, `incarnation_id`, desired `master`, `if_generation` and normal `request_id`. Give this operation a distinct name so an older Hub refuses it instead of ignoring its extra fields on `control_set_master`. Extend `control_list` additively to return selectable candidates, their `incarnation_id`, current generation and nomination state separately from observed attachment status. Indicate when no prepared candidate is available. Label name-only compatibility controls explicitly. Only a new nomination needs live candidate verification. Revocation works for an offline terminal against its durable identity.

Use `0029` on the stated base. Keep bound records outside the `master_session` queries used by name-only calls. Atomic deliberate conversion preserves `legacy_targets_json` and removes the old authorizing row. Prevent concurrent legacy writes, including `PutSessionControl`, from creating or updating a conflicting bound slot. Preserve unrelated legacy grants and independent user/admin/key permissions. Start the bound slot at generation zero and advance its durable revision for each transition, including revocation. Retain enough inactive revision state to reject a delayed create or revoke across a complete nominate/revoke cycle. Retries with the same request ID and input have no further effect. Reject stale generation, different incarnation or owner change. Do not allow a stale first request after re-nomination, even if the destinations are identical. Verify the previous Hub sees `ErrSchemaTooNew` before opening a migrated database, including through its supported upgrade/rollback entry points. [Existing downgrade protection](../../internal/sqlmigrate/migrate.go) · [Legacy grant entry points](../../internal/hub/store/session_control.go)

The Hub accepts `workers_list`, `sessions_list`, `session_snapshot` and `send_text` in this initial adapter. Use typed inner DTOs, a bounded snapshot, normal agent-only, non-forced prompt delivery and its required destination features. Backend filtering must intersect the current two-sided grant, legacy limits, shared targets and existing destination policy for every operation. Zero consenting targets means empty discovery. Pass the same request ID through to destination deduplication and preserve delivery outcomes. This is a mapping of four operations into the new adapter. Other principals retain their existing operations. [Current call registrations](../../internal/hub/workers/session_control_calls.go) · [Destination dispatch](../../internal/hub/workers/route.go)

For each scoped call, check current link, enrollment/owner, lease deadline, incarnation and active generation. At the Router's final admission point after opening the target stream and immediately before sending its operation frame, order that check and the current authoritative target/grant decision with committed revocations. Use a short admission critical section and a consistent store snapshot, with the same ordering for relevant authority transitions. No network wait or destination execution belongs inside a database transaction. A write admitted before a change may already be in flight. Preserve its true outcome. Admission after a committed revoke must fail even when a stale MCP invocation reaches the broker. Keep generic principal paths separate; a bound call has no fallback. Test both orderings with barriers at dispatch, including removal then immediate re-nomination with identical targets.

## Integration acceptance

Use two real native sessions with the same profile and cwd, a real Hub and fixture Workers. Include two simultaneously prepared terminals with only one nominated as well as the unprepared sibling tested in Ticket 1. Demonstrate permitted discovery, one delivered benign task, unchanged sibling tools, removal, and refusal of cached calls under both healthy and failed refresh. Include zero targets, revoked acceptance, a hidden destination, copied pane fields, stale handles against a replacement link, duplicate admin requests, re-enrollment, owner change and restart. Assert independent credentials still work under their established policy while the new scoped interface rejects fallback. Report the server's last successful catalog response separately from actual native display or history. Worker restart requires fresh nomination. Hub restart requires fresh link state and proof of the same surviving Worker incarnation.
