# Proposed A77 decision

For Astra 6.2 high architecture review. Treat these as proposed implementation choices. [Requirements and acceptance](requirements.md), [existing Minion paths](discovery.md), [native capability evidence](capability-matrix.md).

## Architecture card

Use one explicit, session-scoped native attachment backed by the current Minion control graph. Start with Claude Code CLI on a verified terminal host and the existing Go MCP SDK. A launch registers the dormant stdio bridge for that harness invocation alone. The bridge exposes the master tool catalog and concise guidance when its Hub lease matches the active nomination. It withdraws them when the nomination ends or the lease expires. Keeping the static guide in tool descriptions avoids installing an always-visible skill. If needed, add context from a scoped native hook at the next user turn.

The common control path should also serve a future Agent SDK, OpenCode, Gemini or Codex adapter. Each adapter proves the current native session and manages its own exposure. The Hub checks authorization regardless of what the harness has cached.

## Binding and authority

1. **Identify the candidate.** Extend the existing shared-session/event view with an opaque, Worker-issued incarnation and capability status. Local proof combines an authenticated terminal/host instance, its stable session and pane identity, the actual harness process start identity and its current native conversation, when available. Use trustworthy host data, a verified launch/adapter connection and supported lifecycle events. The Hub receives opaque IDs and status. It does not need raw process arguments, home paths or transcript contents. A pane with multiple plausible owners, a linked/ambiguous pane, or an unsupported host remains unbound.
2. **Bind the nomination to the reviewed candidate.** Carry its incarnation in the existing `control_set_master` write and confirm current Worker owner and fresh live observation. Store a separate unique nomination generation. Duplicate delivery keeps the generation. Revocation and re-nomination produce distinct lifetimes even when Worker, name, and scope are identical. A stale capture, request or Undo cannot nominate the replacement. A legacy name-only row receives no new attachment until intentionally bound.
3. **Keep the lease on the trusted path.** A Worker reconciles attached incarnations over its existing authenticated Hub link. The Hub issues a short-lived, opaque capability scoped to the current enrollment, link, incarnation and nomination generation. Keep it in memory at the Worker/adapter boundary. Avoid bearer material in arguments, profiles, environment exports, native chat, logs and generated guides. Use an inherited stdio channel or a local connection with verified peer/launcher provenance. A supplied display name, environment pane ID, native session ID, or socket path is insufficient proof. A transport that serves multiple native conversations needs authenticated per-call session provenance. Test an ordinary same-user peer using copied connection parameters. Protection against arbitrary takeover of the same OS account would require a separate OS or sandbox boundary.
4. **Admit each operation at the Hub.** Validate the lease, live link, incarnation, nomination generation and current grant on admission, with a final dispatch fence for grants revoked during request preparation. Reuse `SessionControl` target computation, Router, authorizer, origin and Worker policy. Admission must intersect the session grant explicitly so the Worker's own-Worker base permissions do not leak into the tool scope. For discovery, filter at the backend and return an empty list if no permitted target exists. Preserve target consent, owner policy, sharing, destination write guards, audit and request identifiers. The scoped backend always routes through this path, including requests that would otherwise be considered local. It must never retry through an API key or an unscoped principal.
5. **Use a narrow native catalog.** Reuse `workers_list`, `sessions_list` and a guarded snapshot. Start task delivery with the existing checked agent prompt path and ordinary native approval. Expose `set_task` only if the UI clearly treats it as a label. Exclude force overrides, shell targets, raw keys, control/management, sharing, provisioning, creation and generic pipe access from the initial catalog. Return the existing delivery outcome, keeping retries deliberate. Instructions and tool descriptions carry no identity proof.

The Worker and Hub negotiate support before attempting an attachment. For backward compatibility, prepare explicit migration for existing name-only rows and old Workers. Bound rows must refuse legacy `source_session`-only master claims. Otherwise a second same-account session can bypass the new attachment gate through the existing local pane field. Maintain current behavior for explicitly unbound legacy nominations while upgrading. Review the old write endpoints and mixed-version rollback for opportunities to erase a bound row's protection implicitly.

## Lifecycle and cleanup

| Event | Required result |
| --- | --- |
| Nominate | A verified, attached candidate receives a fresh lease and loads tools at the native refresh boundary. An unprepared or unsupported harness reports its actual state. A distinct installation step can prepare a future invocation if native live attachment is unavailable. |
| Revoke | Hub removal becomes authoritative at transaction commit. New calls and stale proofs fail. Cancel in-flight work where its backend can still stop safely and preserve the true outcome for already accepted writes. Re-evaluate at routing and cancel streams that outlive lease or generation. |
| Rename, replace, switch or exit | Reject a stale identity promptly, withdraw tools and remove only the attachment's files and processes. Clearing or resuming a conversation requires current native proof and a policy decision on intentional continuation. A new process or ambiguous identity never inherits by name. |
| Drop link, expire, reset or reassign | Stop use immediately when loss is observed and otherwise by the bounded local lease deadline. The Hub checks the authoritative row and authenticated link on each call. Invalidate the relevant memory state and use existing removal/reassignment cleanup. Never queue a master write offline. |
| Restart or recover | Issue a fresh proof on the authenticated replacement link. Reconcile with the same durable nomination only when the original incarnation can be proven. Otherwise await deliberate re-attachment or nomination. Remove owned, expired runtime artifacts after verifying ownership and current references. |

Use the existing watcher/link lifecycle and one bounded reconciliation per Worker with active candidates. Start with short, measured lease and refresh intervals. Make exact latency and load part of the fixture. Keep session-profile overlays under a Minion-owned runtime directory. Use no edit to global/project settings and no restoration of a shared file. Dropping a catalog or removing a file cannot delete previous model context, outputs, or history.

## Alternatives

| Option | Decision and tradeoff |
| --- | --- |
| Copy or delete `SKILL.md` or MCP settings in shared locations | Simple, but races with users and other sessions. Harnesses discover the same paths and may cache their content. It provides no authority revocation. |
| Install a dormant account-wide plugin or edit shared MCP config | Acceptable only as an explicit user-installed dependency for adapters that can project tools per session and verify per-call proof. Automatic profile mutation creates broad exposure and conflicts with the requirement. |
| Per-launch stdio bridge and MCP list-change notifications | Preferred reference path. Reuses the existing protocol and SDK, with an empty catalog off lease. Requires explicit preparation and a version that honors activation and withdrawal. A client that never refreshes must advertise its limit. |
| Native host-managed runtime registration | Claude SDK and some OpenCode deployments offer stronger runtime cleanup when Minion already owns the session handle and the registry is isolated. Portability and lifecycle semantics differ by host. Implement after the shared authorization path and fixture. |
| Process-wide reload or typing activation commands into a discovered pane | Creates unrelated effects or disrupts current work. Session-local launch/attach or an honest unsupported status is the appropriate fallback. |

## Implementation tickets after architecture review

1. **Bind Hub authority and Worker lifecycle.** Add opaque candidate reporting, generation-aware store and owner guards, authenticated lease reconciliation, per-call checks, and compatibility tests. Establish the zero-target state and fail-closed fallback behavior before tool exposure.
2. **Expose a Claude Code attachment.** Bind one Minion stdio catalog and native conversation to a verified invocation. Add and remove only the permitted tool subset and its guidance. Run two simultaneous fixture conversations through real Hub and Worker paths with benign task delivery, revocation, stale credential, restart and native session switch checks.
3. **Show status and qualify additional adapters.** Report actual attachment state in Access > Minion control and add concise setup docs. Validate Codex, Gemini and OpenCode behavior from the matrix against exact releases. Extend only when those native and two-session tests pass. Record installable release evidence under A77 after the prerequisite waves.
