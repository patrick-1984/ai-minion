## Task delivery and scope

- `set_task` records the task label on the target session, as shown by [its executor](../../internal/worker/agent/exec_write.go). Delivering a prompt uses the existing guarded message path. The UI or agent guide should keep the label and delivery outcome clear.
- The current grant registration list does not include provisioning, sharing, update, arbitrary shell execution, or the general pipe API. Pipe send and reply trust follow separate rules. A77 can use the existing approved agent delivery path without combining those policies.
- The legacy discover-and-forward path is account-scoped. Sending an attachment through that path can fall back to the local executor or an API/key principal when its options or target change. The master attachment requires its own sealed backend and explicit grant intersection on destinations. Existing plain CLI/MCP modes can retain their documented semantics while the migration plan for bound nominations is reviewed.
- Source scanning found no component that pushes nomination state into a live harness. The first adapter needs a bounded reconciliation path on the authenticated Worker connection and a distinct session lifecycle attachment.
